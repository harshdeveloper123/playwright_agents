# Inventory Feature — SauceDemo

## Objective

Validate the inventory page displayed after successful authentication to SauceDemo using the existing Playwright framework and Page Object Model (POM).

## Preconditions

- The application is accessible through the existing BASE_URL configuration.
- Inventory tests must use the authenticated browser state generated by the Playwright setup project and stored in playwright/.auth/user.json. Tests must not perform login before each test.
- The authenticated browser state is prepared by the Playwright setup project and saved to `playwright/.auth/user.json`.
- Inventory tests must load this saved authentication state instead of logging in before every test.
- The existing Login Page Object, fixtures, and login helpers should be reused wherever appropriate.

## Scenarios

1. Verify that successful login navigates to the inventory page.
2. Verify that the inventory page displays the expected page heading.
3. Verify that the product inventory is displayed.
4. Verify that each product displays its name, description, price, and image where supported by the application.
5. Verify that products are sorted by name in ascending order by default, if this is the application's documented default behaviour.
6. Verify that products can be sorted by name in descending order.
7. Verify that products can be sorted by price from low to high.
8. Verify that products can be sorted by price from high to low.

## Test Configuration and Data

- Reuse the existing authentication configuration and fixtures to load `playwright/.auth/user.json` for Inventory tests; do not log in before every test.
- Reuse the Login Page Object and authentication helpers in the setup project that creates the saved state, not to repeat the login flow in each Inventory test.
- Do not introduce duplicate login credentials or hardcode credentials in test specifications.
- Use existing application configuration and test data wherever available.

## Framework Rules

- Follow the root `AGENTS.md`.
- Inspect existing locator definitions, Page Objects, fixtures, configuration, and tests before generating files.
- Reuse the existing Login Page Object instead of duplicating login functionality.
- Create or extend an Inventory Page Object and corresponding locator definitions only when needed.
- Store locator definitions in `src/locators/`.
- Store Page Objects in `src/pages/`.
- Store test specifications in `tests/e2e/` using the `.spec.ts` suffix.
- Store the test plan in `specs/`.
- Keep inventory-specific tests separate from the existing Login test specification.
- Do not overwrite or unnecessarily modify existing Login plans, tests, locators, or Page Objects.
- Prefer accessible semantic locators.
- Do not use MCP or live browser inspection during planning or code generation.
- Do not claim tests pass unless actual execution results confirm it.

## Out of Scope

- Adding or removing products from the cart.
- Cart page validation.
- Checkout and payment workflows.
- Login validation scenarios already covered by the Login feature.
